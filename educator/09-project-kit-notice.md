## CodeProbe self-check before submission

This project includes a local CodeProbe kit in the `codeprobe/` folder. Launch the tool with `python3 codeprobe/tools/run_local_server.py` and open `/app/index.html`, or open `codeprobe/app/index.html` directly when your browser permits local Pyodide loading.

Before submission, run CodeProbe on the source code **you authored for this project**. For a multi-file submission, use **Open project ZIP** or **Open folder** and check that `.codeprobeignore` excludes starter code, third-party libraries, generated files, minified assets, build output and documentation. Always inspect the analysed-file and excluded-file lists in the report.

The AI-style concern score is a **formative review signal**, not proof of misconduct. The bundled 60% trigger is provisional. Your instructor may provide a course-local calibration profile that changes the active review trigger. The report will state which trigger was used and whether it was reached.

If your result is above the active trigger, revise the code, run the check again and complete the disclosure note if the module requires it.

A sound submission should be coherent, purposeful, readable and explainable. The objective is not to minimise the score mechanically.

Where manual review is needed, academic judgement will consider the CodeProbe report together with Git history, intermediate commits, tests, design notes and your ability to explain the submitted code.

---

Reports produced by v2.1.9 and later include release metadata and an engine fingerprint where available. This helps identify the kit version used for the report; it does not change the interpretation of the score.
