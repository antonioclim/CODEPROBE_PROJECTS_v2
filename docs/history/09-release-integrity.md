# Phase 9 changeset — release-size reconciliation and deterministic package audit

- Engine version: `2.1.9`
- File report schema: `2.1.9`
- Project report schema: `2.1.9-project`
- Purpose: eliminate ambiguity when two downloaded release ZIPs appear to differ in size.

## Why Phase 9 exists

Phase 8 added dynamic drag-and-drop intake and manual-review guidance, and it was intended to handle GitHub-style ZIP exports. The Phase 9 audit found that common-root stripping for GitHub/hosted ZIP exports needed to be made explicit and test-covered. A concern was then raised that two apparent Phase 8 artefacts differed by approximately 30 kB, with the later-looking one being smaller. The correct response is not to infer missing functionality from ZIP size, but to make release comparison auditable.

## Added

- Conservative common-root stripping for hosted/GitHub ZIP exports before `.codeprobeignore` evaluation.
- `input_packaging` metadata in project reports, including source, detected root and stripping reason.
- `docs/09-release-integrity.md` explaining how to interpret ZIP size changes.
- `tools/compare_releases.py` for package/member-level comparison of two release ZIPs.
- `codeprobe_engine.release.zip_summary()` and `write_zip_summary()`.
- Sidecar package audit generated by `tools/build_release.py`:
  - `.zip.sha256.txt`;
  - `.zip.package_audit.json`.
- `tests/test_phase9_release_integrity.py`.
- `tests/test_phase9_github_zip_roots.py`.

## Changed

- `tools/build_release.py` now writes deterministic ZIP entries with normalised timestamps and permissions.
- `release/release-manifest.json` now records `total_source_size_bytes` in addition to per-file size and SHA-256.
- Project text/JSON reports now expose packaging normalisation so repository-host ZIP handling can be audited.
- Release documentation now distinguishes three different audit quantities: source bytes, compressed member bytes and final ZIP container bytes.

## Interpretation rule

A smaller ZIP can still contain more functionality if the changed files compress well or if redundant/generated material was removed. Conversely, a larger ZIP can contain no meaningful new functionality if the growth is dominated by already-compressed media. For CodeProbe release audit, SHA-256 and member manifest coherence supersede visible ZIP size.
